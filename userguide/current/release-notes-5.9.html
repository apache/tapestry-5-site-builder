Tapestry 5.9

Tapestry 5.9 moves the framework to Jakarta EE 9. Every module that touches the Servlet, Persistence, Validation or CDI APIs now compiles against the jakarta. packages instead of javax..

Because that is a breaking change for existing applications, 5.9 is released twice from two branches: the Jakarta build publishes artifacts with a -jakarta suffix, and the javax build keeps the historical, unsuffixed artifact names. Both carry the same version number and the same features. See Migrating to Jakarta EE for what this means for your project and how to move over.

Tapestry 5.9.1

Tapestry 5.9.1 is a bugfix release and a drop-in replacement for Tapestry 5.9.0.

Improvements Made

  • TAP5-2814 - Upgrade ASM to 9.9

  • TAP5-2758 - Constructor/Builder injection should support @Symbol for List/Collection/Map even without @Inject

Bugs Fixed

  • TAP5-2813 - NPE when @Cached applied to method returning a generic type in multiple classloader mode

Tapestry 5.9.0

Tapestry 5.9.0 is a major release built on Jakarta EE 9.

Highlights:

  • TAP5-2741 and TAP5-2788 - Jakarta EE 9 support. Tapestry now targets Jakarta Servlet 5.0, Jakarta Persistence 3.0, Jakarta Validation 3.0 and Jakarta Inject 2.0. The corresponding javax. imports in your own code have to be changed to jakarta..

  • TAP5-2785 - Separate artifacts for the Jakarta and javax builds. The Jakarta build publishes tapestry-core-jakarta, tapestry-ioc-jakarta and so on, while the javax build keeps publishing tapestry-core, tapestry-ioc and so on. This lets both live side by side in Maven Central at the same version, so projects that cannot move to Jakarta yet can still pick up 5.9.

  • TAP5-2793 - New Recursive component. A Loop-like component that renders its body recursively over parent/child data such as trees and menus, with RecursiveBody marking the insertion point for the children. Objects are adapted to the component through RecursiveValueProvider implementations. This was contributed by KGL PubFactory.

  • TAP5-2799 - Session locking is now explicit. Reading from a Session could lock up a thread. The fix introduces Session.LockMode (NONE, READ, WRITE) together with getAttributeNames(LockMode) and getAttributeNames(String, LockMode) overloads, so the lock a call acquires is now something you can control. See Session Locking.

  • TAP5-2782 - The client-side t5/core/ajax function accepts an options.headers object, so application code can add custom headers to Ajax requests.

  • TAP5-2789 - A migration tool was added to help rewrite Maven and Gradle builds onto the suffixed artifact names.

  • A large round of dependency upgrades came with the Jakarta move, including Hibernate Validator 8, EclipseLink 3.0, Spring 6, Jetty 11 and Apache Commons FileUpload 2.

tapestry-spring now depends on Spring 6, which requires Java 17. The rest of Tapestry still builds for Java 8 bytecode and is tested on Java 11 and 17.

New Features

  • TAP5-2793 - Create a component for rendering recursive data

  • TAP5-2789 - Create Maven configuration tool to assist with suffixed artifacts

  • TAP5-2785 - Change build so it generates separate artifacts for jakarta- and javax-based subprojects

Improvements Made

  • TAP5-2800 - Stylesheets not imported when @Import also imports a library when in multiple classloader mode

  • TAP5-2796 - Upgrade some more dependencies: TestNG, EasyMock, commons-codec, ANTLR, HSQLDB, snakeyaml

  • TAP5-2795 - Upgrade commons-lang dependency to 3.17.0

  • TAP5-2788 - Further changes to upgrade to Jakarta EE

  • TAP5-2782 - ajax.coffee should support more options

  • TAP5-2780 - JSONObject does not conform to equals/hashCode contract

  • TAP5-2778 - JUnit upgrade to support Eclipse 2023-09+

  • TAP5-2777 - Update the closure compiler for better support of modern JavaScript

Dependency Upgrades

  • TAP5-2798 - Change selenium-java and selenium-leg-rc from api to testImplementation

  • TAP5-2771 - Upgrade to Spock 2.3

  • TAP5-2741 - Update to Jakarta EE 9

Bugs Fixed

  • TAP5-2799 - Thread lockup when trying to read from a Session object

  • TAP5-2794 - Upgrade away from vulnerable commons-io and commons-fileupload dependencies

  • TAP5-2792 - POST with body throws exception

  • TAP5-2791 - CssCompressor for CSS files produces wrong minification for the url() function, at least with data URLs

  • TAP5-2790 - Palette with option groups within the SelectModel does not work properly

  • TAP5-2787 - Infinite loop in PageSourceImpl with multiple classloader mode on

  • TAP5-2786 - Attempt to override final method in subclass when in multiple classloader mode

  • TAP5-2783 - Hibernate module initialization fails when entities with compound ids exist

  • TAP5-2779 - Tapestry 5.8.3 to 5.8.7 issues caused by the multiple classloader feature

  • TAP5-2775 - ClassNotFoundException when in production mode and parameter type is array

  • TAP5-2773 - NullPointerException in 5.8.5 when in production mode and template extension points

  • TAP5-2772 - ClassCastException happening in some cases in production mode

  • TAP5-2770 - With multiple classloader mode on, ClassCastException when component and superclass both have @Import

  • TAP5-2605 - JS minimizer regression bug in 5.5.0-beta-1

  • TAP5-2563 - Session replication fails with NotSerializableException on Tapestry class
